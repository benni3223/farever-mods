## Separate social interaction

- `client.PlayerController.update` calls `tryInteractHero` independently of its
  later `Input.isPressed("Interact")` / `tryInteract` loot/NPC path, while input
  is not blocked.
- `tryInteractHero` selects the closest eligible hero. Dead targets use
  `Input.isPressed("Interact")` and `Hero.requestResurrect`. The player-menu
  branch checks combat/enemy eligibility, then `Input.isLongPressed("Interact")`,
  projects the target's native view point, and opens the native interaction menu.
- The mod wraps only that method, with exception-safe scope restoration. Only
  its long-press query is redirected; resurrection and all native eligibility,
  range, positioning, and menu behavior remain in the original function.
- `Input.isLongPressed` stores action-keyed `longPresses` and `bufferedPresses`.
  A released short hold becomes a buffered press. Merely substituting Interact's
  key would cause a social release to trigger loot/NPC interaction, so the mod
  uses its own `MoreSettingsSocialInteract` identity for those records.
- Native `isLongPressed` -> `isDown` / `_isPressed` -> `checkInput` is retained.
  Only the alias's `checkInput` is delegated to native Interact, with a scoped
  replacement in the temporary `getBindings` array. This preserves mode,
  modifier, cinematic, console, and focus checks without registering or mutating
  Data.input, default/user binding records, or the game's saved controls.
- The same alias resolves its bindings for native input-key labels. Gamepad
  active mode takes the original complete Interact path, including press/hold
  suppression and the native pad prompt. The rebind affects keyboard/mouse only.
- Native `LongInputKey.init` forwards its `input` to the child key label, but
  its radial progress callback hardcodes Interact. A subsequent callback on
  HeroWidget-owned hints selects the proper action and corrects only the social
  progress, using the native LongPressDuration and OFFSET. Dead allies keep the
  native revive key; other widgets are not touched. Rebuild occurs only when
  the action changes; native child key labels already refresh changed bindings.
- Disabling/changing the setting and scene disposal clear only the alias's hold
  and buffered-press records. Disabled behavior and existing controls are default.

## Healing and critical heals

- `BaseSkill.evalHeal` ends in `HitData.criticalRoll`. Its roll checks the
  skill's `canCrit`, blocked state, and hit eligibility before setting Critical.
  `Skill.canCrit` allows hero skills; `Status.canCrit` returns true.
  `HitData.canCrit` excludes consumables, rather than excluding heals.
- `Unit.computeHeal` multiplies critical heals by `hitData.critDmgMult`.
  Therefore critical healing is supported, but not every healing source can crit.
- `Unit.rpcDisplayHeal__impl` routes eligible floating numbers to `HealDisplay`.
  The inherited `DamageDisplay` constructor gets `isCrit` from
  `DamageResult.get_critical`. No crits or values are synthesized by the mod.
- `HealDisplay.init` calls `DamageDisplay.init` before switching its component
  to heal-display. The base hook skips healing, and the subclass postfix styles
  it once after native initialization. Native visibility, number formatting, icons, fonts, animations, and heal
  calculations stay native.
- Healing clears the native tint/shadow and uses the existing glyph-aligned
  shader ramps and single 1 px black outline. Normal: B8FF92 -> 238C45. Critical:
  FFD966 -> B8FF92 -> 238C45, with its middle stop at half glyph height. No new
  per-number textures or additional per-frame entity scans are introduced.

## Received-healing follow-up

The screenshot's `+500` number is generated by `EffectsFeed.displayHeal`, not
`HealDisplay`. `Unit.rpcDisplayHeal__impl` routes heals received by the local
player to this feed before reaching its other-target HealDisplay branch.

The new `EffectsFeed.displayHeal` postfix styles the last native row's FmtText
using the same shared healing renderer and `DamageResult.get_critical` flag.
The inspected method adds exactly one row above its scaled-amount threshold and
then assigns the `heal` class. Match that threshold before looking at the last
row so a suppressed heal cannot restyle a previous one. Reading the appended row
after the native call also accommodates Performance improvements trimming older
rows. Only the new row's text is styled: the native `+` sign, scaling/rounding,
row scheduling, container alpha/fades, and non-healing notifications are retained.
There is no feed-history scan or per-frame work.

Regression coverage includes received normal and critical heals, sub-one scaled
heals, the one-point boundary, disabled styling, a trimmed one-row feed, earlier
healing rows and other notifications, the literal `+500`, native timing/alpha,
and the rendered gradient endpoints.
